# Event type id is a slug chosen by the owner

An event type is identified by a slug the owner types when creating it (`[a-z0-9-]{1,40}`, uppercase is rejected rather than normalized, duplicates give `409 event_type_exists`), and that slug is its only id: it appears in guest URLs (`/book/:eventTypeId`), in API paths (`/api/event-types/{id}`) and in every stored booking. We rejected a server-generated id with a separate slug field: it would let a type be renamed without breaking links, but adds a second identifier to explain and keep unique, and the original requirements already describe the type's `id` as something the owner supplies. The cost is that an id can never change, so a typo in a slug is permanent; types cannot be edited or deleted in the MVP, which keeps that cost small, but adding editing later means deciding whether ids stay frozen or links get redirects.
